# Права пользователей в amoCRM

Урок Bizandsoft объясняет матрицу прав по сущностям и действиям, ограничения по этапам и полям, а также общие роли. Важный вывод: права нельзя оценивать по одному переключателю, поскольку доступ к сделке может влиять на задачу или связанный элемент списка. Источники: [транскрипт](transcript.md) и [сведения страницы](page.md), длительность 18:10.

## Пользователи, группы и матрица доступа

Для изменения прав нужен доступ администратора. Пользователь добавляется в настройках через имя, почту и группу; ему приходит приглашение. Если email уже зарегистрирован, автор показывает добавление существующего пользователя по найденному адресу, а не создание второй учетной записи (00:00–01:38).

Группа соответствует отделу. Она используется для прав, фильтров, аналитики и назначения действий в цифровой воронке. При выборе группы целиком состав сотрудников можно менять без редактирования каждого триггера (00:36).

В матрице строки представляют сущности: сделки, контакты, компании, задачи и списки. Столбцы представляют операции: создание, просмотр, редактирование, удаление и экспорт. Создание разрешается либо запрещается. Для большинства остальных операций над сделками, контактами и компаниями доступны уровни:
- Запрещено.
- Только для карточек, где пользователь ответственный.
- Для своих карточек и карточек членов группы.
- Для всех карточек.

Настройки связаны: запрет просмотра автоматически ограничивает правку, удаление и экспорт; запрет правки ограничивает удаление (02:12–03:50). Поэтому перед проверкой отдельной операции нужно учитывать итоговую комбинацию прав.

## Особенности задач

Исполнение задачи не считается ее редактированием. Пользователь может записать результат и закрыть свою задачу, даже если изменение и удаление задач запрещены (06:07–06:40).

Права карточки, в которой находится задача, могут иметь приоритет над ограничениями самой задачи. В примере Игнат редактирует собственную сделку и может менять срок, ответственного и удалять задачу в ней. В чужой доступной только для просмотра сделке он может исполнить назначенную на него задачу, но не редактировать ее (07:17–08:18).

Для более строгого ограничения автор отдельно демонстрирует сторонний виджет запрета редактирования задач. В нем настраиваются запреты изменения срока, ответственного, текста, закрытия без результата и работы с чужими задачами; при включении лога попытки изменения записываются в карточку (08:18–09:26). Это возможности дополнительного решения, а не обычных переключателей матрицы.

## Списки, этапы и поля

Каждому списку задаются собственные права. Кроме общего разрешения или запрета автор показывает режим «Внутри сделки»: доступ к прикрепленному элементу списка определяется правами на эту сделку. Например, менеджер не видит общий набор счетов, но может работать со счетом своей сделки в пределах ее разрешений. Новый список по умолчанию закрыт для обычных пользователей, администратор имеет доступ (09:26–11:36).

Для «Неразобранного» права задаются отдельно по каждой воронке. Особые права можно назначать этапам. Если просмотр этапа запрещен, сам столбец остается виден, а сделки в нем скрыты, включая собственные. В примере пользователь может перевести сделку на закрытый для него этап, получает предупреждение и после этого теряет доступ к карточке (12:12–13:51).

Опция «Суперполя» позволяет ограничивать отдельные поля. Закрытое для просмотра поле скрыто полностью; доступное только для чтения видно, но не редактируется. Автор показывает разделение полей для разных отделов на примере источника и скидки (13:51–14:58).

## Почта, файлы и роли

Отдельный флажок регулирует работу с общей почтой. Отключение доступа к разделу файлов убирает пункт «Файлы» из списков, однако не запрещает сотруднику добавлять файлы в собственные сделки (14:58–15:33).

Роль сохраняет набор прав для повторного применения. Изменение роли обновляет права всех пользователей, которым она назначена. При удалении роли можно оставить индивидуальные настройки или перевести сотрудников на другую роль (15:33–16:36). Группа и роль решают разные задачи: первая объединяет сотрудников по принадлежности, вторая задает общий набор разрешений.

Лог авторизаций позволяет смотреть входы пользователей и сведения об экспорте с фильтрами. Белый список IP ограничивает вход избранными адресами (17:07–17:40).

## Дополнительная демонстрация

В отдельном блоке автор показывает виджет биржи лидов: менеджер с доступом только к собственным сделкам может брать отобранные чужие сделки в работу. Для отбора используются статусы, поля и теги, видимость отдельных данных до взятия сделки и ограничение количества сделок. Это расширение для сценариев, которые не покрывает обычное «Неразобранное» (04:32–05:35).

## Проверка настроенной роли

Проверить собственную и чужую сделку, карточку участника группы, задачу внутри каждого случая, элемент списка и переход в закрытый этап. Затем проверить чтение и изменение особых полей, работу с общей почтой и файлами. При проверке роли учитывать, что изменение ее настроек затрагивает всех назначенных пользователей.
